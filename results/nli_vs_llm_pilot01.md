# NLI vs LLM entailment — pilot01

Measures whether local NLI can replace the LLM judge (`eval.entailment.backend: nli`,
`cross-encoder/nli-deberta-v3-base`, CPU, deterministic) on pilot01. It compares against the
stored LLM verdicts: `reports/gold_verified_pilot01.json` (judge gpt-4.1-mini) and
`reports/gold_verified_pilot01.judge-gpt54.json` (judge gpt-5.4, the reference for how much two
LLM judges agree). Redundancy is compared against `reports/redundancy_pilot01.json`.

**Caveat first.** The NLI formulation below is a **retune on the evaluation pairs**
(no held-out set). The bias favours NLI, so the negative conclusion stands. The
large-model and formulation-step numbers come from exploratory scratch runs with no
committed raw verdicts, so they are *indicative, not reportable*.

**Provenance.** NLI runs: `scripts/eval/verify_gold.py --entailment nli --max-cost 0
--reports-dir <scratch> --out <scratch>/pilot01_questions_nli.jsonl` and
`scripts/dataset/redundancy.py --entailment nli --max-cost 0 --reports-dir <scratch>`
(an nli run may not write `tests/regression` or `reports/`), corpus `2f3b35f27e86caf8`, on
the code of the zero-cost-mode commit. Raw NLI verdicts: `results/nli_pilot01/`. Answerer replies were cache-only (100 calls, 100 cached),
there were 0 judge calls, and the run total was **$0.0000** (both runs append $0 rows to
`reports/llm_ledger.jsonl`). A second run was byte-identical to the first.

## Findings

1. **NLI is not a drop-in replacement for the LLM judge on this task.**
   - Unit-level κ against the LLM judges is **0.31** (gpt-4.1-mini) and **0.36** (gpt-5.4).
   - The two LLM judges agree with each other at **0.85**.
   - Type labels agree on 10/25 questions, and NLI drops 14/25 questions where the LLM judges drop 0 or 1.
2. **Most of the gap is in grading, not unit entailment.** 13 of the 15 type differences
   happen because the NLI grader fails a full-corpus answer the LLM grader passed. The grader
   hypothesis is *question + reference fact*, and a correct answer does not restate the
   question. Example, A5:
   - Question: "In the live demo, how long did the baseline query take and how long was the video?"
   - Answer: "The baseline query took 4 minutes, and the video was 6 hours long." (correct)
   - Result: rejected, because the answer does not entail the question clause.

   Question-conditioning was added to lift unit-level agreement (below); in grading it works
   against correct answers.
3. **Redundancy disagrees even more.**
   - Overall κ is **0.17**; the deck pairs are at chance (−0.02, −0.10).
   - Deck bullets are fragments ("Query Time Analysis: Too Slow"), not propositions an NLI model can test.
   - The intake decision would flip. deck→transcript falls from 94.2% (LLM) to 59.6% (NLI),
     below the 0.65 bar (`dataset.intake.max_deck_to_transcript`), so pilot01 would be KEPT
     under NLI where the LLM judge REJECTs it.
4. **A bigger NLI model does not close the gap.**
   `MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli`, on the same 147 unit pairs with
   the shipped formulation, reached κ 0.35 / 0.35 against the two LLM judges. It is slower,
   but no speed ratio is reported: the one timing was taken while other jobs shared the CPU,
   which fails the latency measurement rule (idle machine, 3 repeats, median).
   *Corrected 2026-09-23: an earlier version of this report gave "~17× the runtime
   (2,295 s vs 132 s)" from that uncontrolled run.*

Formulation steps measured on the same 147 unit pairs (unit-level κ vs gpt-4.1-mini / gpt-5.4):

| NLI formulation | κ vs 4.1-mini | κ vs 5.4 |
|---|---:|---:|
| answer facts, naive sentence split (first version) | 0.22 | 0.21 |
| + initials-safe split ("Phillip B. Gibbons") and a ≥4-word premise | 0.27 | 0.27 |
| + question-conditioned hypothesis (**shipped**) | 0.31 | 0.36 |

These choices were made on the evaluation pairs themselves; there is no held-out set, so treat
0.31/0.36 as an upper estimate for this formulation.

**Consequence.** *Hypothesis, not measured:* NLI may still suit claim-level checks on
generated answers, whose claims *are* propositions. Gold verification and
the intake redundancy gate should not rely on NLI. The zero-cost way to keep an LLM judge is
a free backend (`LINKRAG_JUDGE_BACKEND=groq`). Measure its agreement the same way before
trusting it.

*Corrected 2026-09-23 (after a design review): caveat moved first, the formulation labelled a retune, the claim-level suggestion marked as a hypothesis, and the provenance commands given as actually run.*
